class="chakra-menu__menu-list css-1eylv19"></div></div></div><div class="theme-doc-markdown markdown"><header><h1>Calico Open Source 3.31 release notes</h1></header>
<p>Learn about the new features, bug fixes, and other updates in this release of Calico.</p>
<h2 class="anchor anchorTargetStickyNavbar_DLFK" id=new-features-and-enhancements>New features and enhancements<a href=#new-features-and-enhancements class=hash-link aria-label="Direct link to New features and enhancements" title="Direct link to New features and enhancements" translate=no>​</a></h2>
<h3 class="anchor anchorTargetStickyNavbar_DLFK" id=streamlined-ebpf-data-plane-installation>Streamlined eBPF data plane installation<a href=#streamlined-ebpf-data-plane-installation class=hash-link aria-label="Direct link to Streamlined eBPF data plane installation" title="Direct link to Streamlined eBPF data plane installation" translate=no>​</a></h3>
<p>You can now easily install Calico with the eBPF data plane on most on-prem clusters (like those created using kubeadm), without manual configuration.
This new automated flow is enabled by setting parameters in the Installation API.</p>
<p>Previously, installing Calico with the eBPF data plane required a series of manual steps to manage kube-proxy and API service endpoints.
Now, the Tigera Operator handles all the necessary networking setup and kube-proxy disabling automatically, ensuring a seamless transition.</p>
<p>This new default behavior simplifies both fresh installations and switching an existing cluster's data plane from iptables to eBPF.
You can still use the manual setup process if needed.</p>
<p>see <a class="" href=/calico/3.31/getting-started/kubernetes/self-managed-onprem/onpremises>Install Calico networking and network policy for on-premises deployments</a>.</p>
<h3 class="anchor anchorTargetStickyNavbar_DLFK" id=nftables-data-plane>nftables data plane<a href=#nftables-data-plane class=hash-link aria-label="Direct link to nftables data plane" title="Direct link to nftables data plane" translate=no>​</a></h3>
<p>The nftables data plane is now generally available.</p>
<p>This enhancement leverages the Service implementation in Kubernetes 1.31 that uses nftables for network filtering, promising better performance and scalability compared to the default iptables implementation.
You can deploy Calico Open Source in nftables mode to provide a robust networking and network policy implementation that is fully compatible with the upstream kube-proxy utilizing nftables.</p>
<p>For more information, see the <a class="" href=/calico/3.31/getting-started/kubernetes/nftables>nftables data plane guide</a>.</p>
<h3 class="anchor anchorTargetStickyNavbar_DLFK" id=calico-ingress-gateway>Calico Ingress Gateway<a href=#calico-ingress-gateway class=hash-link aria-label="Direct link to Calico Ingress Gateway" title="Direct link to Calico Ingress Gateway" translate=no>​</a></h3>
<p>Calico Ingress Gateway is now generally available.</p>
<p>Calico Ingress Gateway manages cluster ingress traffic using the Kubernetes Gateway API, the standardized successor to the Ingress resource.
It is a hardened distribution of the Envoy Gateway project, and the Tigera Operator manages its full lifecycle.</p>
<p>For more information, see <a class="" href=/calico/3.31/networking/ingress-gateway/about-calico-ingress-gateway>Calico Ingress Gateway</a>.</p>
<h3 class="anchor anchorTargetStickyNavbar_DLFK" id=dscp-marking>DSCP marking<a href=#dscp-marking class=hash-link aria-label="Direct link to DSCP marking" title="Direct link to DSCP marking" translate=no>​</a></h3>
<p>This release enhances your Quality of Service (QoS) controls by enabling you to set Differentiated Services Code Point (DSCP) markings on your outgoing network traffic.
This capability is important for ensuring network prioritization for applications sensitive to latency or requiring differentiated treatment across a shared network.
You can now assign a DSCP value directly to packets originating from your Kubernetes pods and Calico host endpoints using the new <code>qos.projectcalico.org/dscp</code> annotation.
This approach moves the configuration of traffic priority from the network infrastructure layer to the application layer, giving you more reliable and enduring control.</p>
<p>For more details on setting this up, check the <a class="" href=/calico/3.31/networking/configuring/qos-controls#configure-diffserv>Configure QoS Controls</a>.</p>
<h3 class="anchor anchorTargetStickyNavbar_DLFK" id=quality-of-service-controls-for-ebpf>Quality of Service controls for eBPF<a href=#quality-of-service-controls-for-ebpf class=hash-link aria-label="Direct link to Quality of Service controls for eBPF" title="Direct link to Quality of Service controls for eBPF" translate=no>​</a></h3>
<p>We added support for QoS controls with eBPF.
If your cluster uses Calico's eBPF data plane, you can now use QoS controls for bandwidth limits, packet rate limits, and DSCP marking.</p>
<p>For more information, see <a class="" href=/calico/3.31/networking/configuring/qos-controls>Configure QoS controls</a>.</p>
<h3 class="anchor anchorTargetStickyNavbar_DLFK" id=full-interface-address-coverage-for-auto-host-endpoints>Full interface address coverage for auto host endpoints<a href=#full-interface-address-coverage-for-auto-host-endpoints class=hash-link aria-label="Direct link to Full interface address coverage for auto host endpoints" title="Direct link to Full interface address coverage for auto host endpoints" translate=no>​</a></h3>
<p>You can now ensure that host endpoints automatically capture all IPv4 and IPv6 addresses across every network interface on your node.
This capability is essential for a robust and consistent security posture because it ensures that all IP addresses associated with a host are correctly mapped and protected by your network policies.
To manage which interfaces are included, you can use the new <code>interfacePattern</code> field in your <code>HostEndpointTemplate</code> within the <code>KubeControllersConfiguration</code>.</p>
<p>For documentation and configuration examples, see <a class="" href=/calico/3.31/reference/resources/kubecontrollersconfig>Kubernetes controllers configuration</a>.</p>
<h3 class="anchor anchorTargetStickyNavbar_DLFK" id=fine-grained-bgp-control-with-per-peer-local-as-number>Fine-grained BGP control with per-peer local AS number<a href=#fine-grained-bgp-control-with-per-peer-local-as-number class=hash-link aria-label="Direct link to Fine-grained BGP control with per-peer local AS number" title="Direct link to Fine-grained BGP control with per-peer local AS number" translate=no>​</a></h3>
<p>You can now configure a distinct local AS number for each external BGP peer by using the new <code>localASNumber</code> field in the <code>BGPPeer</code> resource.</p>
<p>This capability is essential for multi-homed topologies and environments where border nodes must peer with external networks, like government agencies, that require a specific local Autonomous System Number (ASN) different from the cluster's global or node-specific ASN configured in the <code>BGPConfiguration</code> resource.
This new field allows you to override the default ASN on a per-peer basis, removing the need to dedicate entire nodes to a single external peer.</p>
<p>If the <code>localASNumber</code> field is not set for a peer, Calico will automatically fall back to using the global or node-wide ASN as before, ensuring no change to your existing BGP behavior.</p>
<p>For more information, see the documentation on <a class="" href=/calico/3.31/networking/configuring/bgp#set-a-local-as-number-for-a-specific-bgp-peer>Set a local AS number for a specific BGP peer</a>.</p>
<h3 class="anchor anchorTargetStickyNavbar_DLFK" id=ebpf-data-plane-lru-connection-tracking>eBPF data plane: LRU connection tracking<a href=#ebpf-data-plane-lru-connection-tracking class=hash-link aria-label="Direct link to eBPF data plane: LRU connection tracking" title="Direct link to eBPF data plane: LRU connection tracking" translate=no>​</a></h3>
<p>You can now ensure superior service availability and performance under heavy network load with the introduction of the Least Recently Used (LRU) hash map for connection tracking (conntrack) in the eBPF data plane.</p>
<p>By switching to an LRU hash map, the conntrack system gains an intelligent, automatic eviction policy that removes the oldest, least recently used entries to make room for new connections, preventing network errors and dropped connections.</p>
<h3 class="anchor anchorTargetStickyNavbar_DLFK" id=openstack-immediate-neutron-qos-policy-application>OpenStack: Immediate Neutron QoS policy application<a href=#openstack-immediate-neutron-qos-policy-application class=hash-link aria-label="Direct link to OpenStack: Immediate Neutron QoS policy application" title="Direct link to OpenStack: Immediate Neutron QoS policy application" translate=no>​</a></h3>
<p>Updates to OpenStack Neutron Quality of Service (QoS) policies are now applied immediately, minimizing configuration delays in large-scale environments.
Previously, policy changes relied on a slow, periodic resync process that could take a long time in large clusters.
With this enhancement, Calico responds to all QoS policy and rule changes on the Neutron API in real-time, enforcing network requirements within seconds and ensuring tenants have a consistent, reliable network experience.</p>

<h4 class="anchor anchorTargetStickyNavbar_DLFK" id=updating-6>Updating<a href=#updating-6 class=hash-link aria-label="Direct link to Updating" title="Direct link to Updating" translate=no>​</a></h4>
<p>To update a previous version of Calico, see <a class="" href=/calico/3.31/operations/upgrading/>our upgrade guides</a>.</p>
<p>If you use Calico Ingress Gateway, this release bumps the bundled Envoy Gateway to v1.8.0, which requires the Gateway API v1.5.1 CRDs. Envoy Gateway v1.8 watches <code>TLSRoute</code>, <code>ListenerSet</code>, and <code>BackendTLSPolicy</code> at <code>gateway.networking.k8s.io/v1</code>. If those CRDs are still served only at an older version, for example <code>v1alpha2</code>, the <code>envoy-gateway</code> pod fails to start with <code>no matches for kind "TLSRoute" in version "gateway.networking.k8s.io/v1"</code>.</p>
<p>If the Tigera Operator manages your Gateway API CRDs (the default), set <code>crdManagement: Reconcile</code> on the <code>GatewayAPI</code> resource so the operator upgrades the CRDs during the upgrade. If a <code>safe-upgrades.gateway.networking.k8s.io</code> ValidatingAdmissionPolicy blocks the upgrade with <code>Installing experimental CRDs on top of standard channel CRDs is prohibited</code>, delete that policy and its binding, then let the operator reconcile. The operator recreates the policy afterward.</p>
<p>If you manage the Gateway API CRDs yourself, install the Gateway API v1.5.1 CRDs before upgrading.</p>

<li class="">Fixes an issue in nftables mode where Felix could panic when reading back an IP set member it could not parse. <a href=https://github.com/projectcalico/calico/pull/13442 target=_blank rel="noopener noreferrer" class="">calico 13442</a> (@caseydavenport)</li>
<li class="">Fixes an issue where IP sets containing overlapping CIDRs could fail to program correctly in nftables mode after a member was removed. <a href=https://github.com/projectcalico/calico/pull/13441 target=_blank rel="noopener noreferrer" class="">calico 13441</a> (@caseydavenport)</li>
<li class="">Fixes CALICO_IPV6POOL_VXLAN being ignored in IPv6-only clusters where the IPv4 pool is disabled (CALICO_IPV4POOL_CIDR=none), which left the IPv6 pool without VXLAN encapsulation. <a href=https://github.com/projectcalico/calico/pull/13439 target=_blank rel="noopener noreferrer" class="">calico 13439</a> (@caseydavenport)</li>

<li class="">Fixed the bundled Envoy Gateway crash-looping on clusters whose Gateway API CRD set omits ListenerSet, TLSRoute or BackendTLSPolicy, such as OpenShift or GKE's managed Gateway API addon. <a href=https://github.com/projectcalico/calico/pull/13367 target=_blank rel="noopener noreferrer" class="">calico 13367</a> (@electricjesus)</li>
<li class="">Fixed a bug where Calico could advertise a Service IP over BGP from a node whose local endpoint was not Ready, causing connection failures. <a href=https://github.com/projectcalico/calico/pull/13255 target=_blank rel="noopener noreferrer" class="">calico 13255</a> (@MichalFupso)</li>

<li class="">Fixed a latent bug where EnsureBlock could allocate an IPv6 block from the wrong IP pool when an explicit IPv6 pool selector was provided (Windows host-local IPAM block reservation). <a href=https://github.com/projectcalico/calico/pull/13215 target=_blank rel="noopener noreferrer" class="">calico 13215</a> (@fasaxc)</li>

<li class="">eBPF dataplane: fix loss of connectivity to the Kubernetes API server service after the API server is unavailable for a period, when using bpfNetworkBootstrap. Felix no longer clears the API server service's NAT backend when its endpoints transiently empty, so connectivity recovers without a calico-node restart. <a href=https://github.com/projectcalico/calico/pull/13066 target=_blank rel="noopener noreferrer" class="">calico 13066</a> (@lucastigera)</li>
