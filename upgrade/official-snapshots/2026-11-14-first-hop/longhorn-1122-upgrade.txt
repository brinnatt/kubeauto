has-extra-bottom-padding"><p>Here we cover how to upgrade to the latest Longhorn from all previous releases.</p><h1 id=deprecation--incompatibility>Deprecation & Incompatibility</h1><p>There are no deprecated or incompatible changes introduced in v1.12.2.</p><h1 id=upgrade-path-enforcement-and-downgrade-prevention>Upgrade Path Enforcement and Downgrade Prevention</h1><p>Starting with v1.5.0, Longhorn only supports upgrades from one minor version to the next. For example, upgrading from 1.5.x to 1.6.x is supported, but skipping versions (e.g., from 1.4.x to 1.6.x) is not. If you attempt to upgrade from an unsupported version or skip a minor version, the operation will fail automatically. However, you can revert to the previously installed version without service interruption or downtime.</p><p>Moreover, Longhorn does not support downgrades to earlier versions. This restriction helps prevent unexpected system behavior and issues associated with function incompatibility, deprecation, or removal.</p><blockquote><p><strong>Warning</strong>:</p><ul><li>Once you successfully upgrade to v1.12.2, you will not be allowed to revert to the previously installed version.</li><li>The Downgrade Prevention feature was introduced in v1.5.0 so Longhorn is unable to prevent downgrade attempts in older versions.
However, downgrading is completely unsupported and is therefore not recommended.</li></ul></blockquote><p>The following table outlines the supported upgrade paths.</p><table><thead><tr><th style=text-align:center>Current version</th><th style=text-align:center>Target version</th><th style=text-align:center>Supported</th><th style=text-align:center>Example</th></tr></thead><tbody><tr><td style=text-align:center>x.y.*</td><td style=text-align:center>x.(y+1).*</td><td style=text-align:center>✓</td><td style=text-align:center>v1.4.2 to v1.5.1</td></tr><tr><td style=text-align:center>x.y.*</td><td style=text-align:center>x.y.(*+n)</td><td style=text-align:center>✓</td><td style=text-align:center>v1.5.0 to v1.5.1</td></tr><tr><td style=text-align:center>x.y<sup id=fnref:1><a href=#fn:1 class=footnote-ref role=doc-noteref>1</a></sup>.*</td><td style=text-align:center>(x+1).y.*</td><td style=text-align:center>✓</td><td style=text-align:center>v1.30.0 to v2.0.0</td></tr><tr><td style=text-align:center>x.(y-1).*</td><td style=text-align:center>x.(y+1).*</td><td style=text-align:center>X</td><td style=text-align:center>v1.3.3 to v1.5.1</td></tr><tr><td style=text-align:center>x.(y-2).*</td><td style=text-align:center>x.(y+1).*</td><td style=text-align:center>X</td><td style=text-align:center>v1.2.6 to v1.5.1</td></tr></tbody></table><h2 id=manual-checks-before-upgrade>Manual Checks Before Upgrade</h2><p>Automated checks are only performed on some upgrade paths, and the pre-upgrade checker may not cover some scenarios. Manual checks, performed using either kubectl or the UI, are recommended for these schenarios. You can take mitigating actions or defer the upgrade until issues are addressed.</p><ul><li>Ensure that all V2 Data Engine volumes are detached and the replicas are stopped. The V2 Data Engine currently does not support live upgrades.</li><li>Avoid upgrading when volumes are in the &ldquo;Faulted&rdquo; status. If all the replicas are deemed unusable, they may be deleted and data may be permanently lost (if no usable backups exist).</li><li>Avoid upgrading if a failed BackingImage exists. For more information, see <a href=../../advanced-resources/backing-image/backing-image>Backing Image</a>.</li><li>It is recommended to create a <a href=../../advanced-resources/system-backup-restore/backup-longhorn-system>Longhorn system backup</a> before performing the upgrade. This ensures that all critical resources, such as volumes and backing images, are backed up and can be restored in case any issues arise.</li></ul><h1 id=upgrading-longhorn>Upgrading Longhorn</h1><p>There are normally two steps in the upgrade process: first upgrade Longhorn manager to the latest version, then manually upgrade the Longhorn engine to the latest version using the latest Longhorn manager.</p><h2 id=1-upgrade-longhorn-manager>1. Upgrade Longhorn manager</h2><ul><li>To upgrade from v1.11.x, see <a href=./longhorn-manager>this section.</a></li></ul><h2 id=2-manually-upgrade-longhorn-engine>2. Manually Upgrade Longhorn Engine</h2><p>After Longhorn Manager is upgraded, Longhorn Engine also needs to be upgraded <a href=./upgrade-engine>using the Longhorn UI.</a></p><h2 id=3-automatically-upgrade-longhorn-engine>3. Automatically Upgrade Longhorn Engine</h2><p>Since Longhorn v1.1.1, we provide an option to help you <a href=./auto-upgrade-engine>automatically upgrade engines</a></p><h2 id=4-automatically-migrate-recurring-jobs>4. Automatically Migrate Recurring Jobs</h2><p>With the introduction of the new label-driven <code>Recurring Job</code> feature, Longhorn has removed the <code>RecurringJobs</code> field in the Volume Spec and planned to deprecate <code>RecurringJobs</code> in the StorageClass.</p><p>During the upgrade, Longhorn will automatically:</p><ul><li>Create new recurring job CRs from the <code>recurringJobs</code> field in Volume Spec and convert them to the volume labels.</li><li>Create new recurring job CRs from the <code>recurringJobs</code> in the StorageClass and convert them to the new <code>recurringJobSelector</code> parameter.</li></ul><p>Visit <a href=../../snapshots-and-backups/scheduling-backups-and-snapshots>Recurring Snapshots and Backups</a> for more information about the new <code>Recurring Job</code> feature.</p><h1 id=extended-reading>Extended Reading</h1><p>Visit <a href=https://longhorn.io/kb/troubleshooting-some-old-instance-manager-pods-are-still-running-after-upgrade>Some old instance manager pods are still running after upgrade</a> for more information about the cleanup strategy of instance manager pods during upgrade.</p><h1 id=need-help>Need Help?</h1><p>If you have any issues, please report it at
<a href=https://github.com/longhorn/longhorn/issues>https://github.com/longhorn/longhorn/issues</a> and include your backup yaml files
as well as manager logs.</p><div class=footnotes role=doc-endnotes><hr><ol><li id=fn:1><p>Longhorn only allows upgrades from any patch version of the last minor release before the new major version.
