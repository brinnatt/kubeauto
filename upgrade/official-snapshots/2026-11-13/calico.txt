<h2 class="anchor anchorWithStickyNavbar_nkN5" id=kubernetes-requirements>Kubernetes requirements<a href=#kubernetes-requirements class=hash-link aria-label="Direct link to Kubernetes requirements" title="Direct link to Kubernetes requirements" translate=no>​</a></h2>
<h4 class="anchor anchorWithStickyNavbar_nkN5" id=supported-versions>Supported versions<a href=#supported-versions class=hash-link aria-label="Direct link to Supported versions" title="Direct link to Supported versions" translate=no>​</a></h4>
<p>We test Calico v3.28 against the following Kubernetes versions. Other versions may work, but we are not actively testing them.</p>
<ul>
<li>v1.27</li>
<li>v1.28</li>
<li>v1.29</li>
<li>v1.30</li>
</ul>
<p>Due to changes in the Kubernetes API, Calico v3.28 will not work
on Kubernetes v1.20 or below. v1.21 may work, but is no longer tested.
Newer versions may also work, but we recommend upgrading to a version of Calico
that is tested against the newer Kubernetes version.</p>
<h4 class="anchor anchorWithStickyNavbar_nkN5" id=cni-plug-in-enabled>CNI plug-in enabled<a href=#cni-plug-in-enabled class=hash-link aria-label="Direct link to CNI plug-in enabled" title="Direct link to CNI plug-in enabled" translate=no>​</a></h4>
<p>Calico must be installed as a CNI plugin in the container runtime.</p>
<p>This installation must use the Kubernetes default CNI configuration directory (<code>/etc/cni/net.d</code>) and binary directory (<code>/opt/cni/bin</code>).</p>
<h4 class="anchor anchorWithStickyNavbar_nkN5" id=other-network-providers>Other network providers<a href=#other-network-providers class=hash-link aria-label="Direct link to Other network providers" title="Direct link to Other network providers" translate=no>​</a></h4>
<p>Generally, you cannot use Calico together with another network provider.</p>
<p>Notable exceptions include the following:</p>
<ul>
<li><a href=/calico/3.28/getting-started/kubernetes/flannel/>flannel</a></li>
<li>Platform-specific CNIs, such as the <a href=https://github.com/aws/amazon-vpc-cni-k8s/blob/master/README.md target=_blank rel="noopener noreferrer">AWS VPC CNI</a> and <a href=https://github.com/Azure/azure-container-networking/blob/master/docs/cni.md target=_blank rel="noopener noreferrer">Azure VNET CNI</a> plugins.</li>
</ul>
<p>If you're working with a cluster that already uses another CNI, you cannot migrate to Calico.</p>
<h4 class="anchor anchorWithStickyNavbar_nkN5" id=supported-kube-proxy-modes>Supported kube-proxy modes<a href=#supported-kube-proxy-modes class=hash-link aria-label="Direct link to Supported kube-proxy modes" title="Direct link to Supported kube-proxy modes" translate=no>​</a></h4>
<p>Calico supports the following kube-proxy modes:</p>
<ul>
<li><code>iptables</code> (default)</li>
<li><code>ipvs</code> Requires Kubernetes ≥  v1.9.3. Refer to
<a href=/calico/3.28/networking/configuring/use-ipvs>Use IPVS kube-proxy</a> for more details.</li>
</ul>
<h4 class="anchor anchorWithStickyNavbar_nkN5" id=ip-pool-configuration>IP pool configuration<a href=#ip-pool-configuration class=hash-link aria-label="Direct link to IP pool configuration" title="Direct link to IP pool configuration" translate=no>​</a></h4>
<p>The IP range selected for pod IP addresses cannot overlap with any other
IP ranges in your network, including:</p>
<ul>
<li>The Kubernetes service cluster IP range</li>
<li>The range from which host IPs are allocated</li>
</ul>
<h2 class="anchor anchorWithStickyNavbar_nkN5" id=application-layer-policy-requirements>Application layer policy requirements<a href=#application-layer-policy-requirements class=hash-link aria-label="Direct link to Application layer policy requirements" title="Direct link to Application layer policy requirements" translate=no>​</a></h2>
<ul>
<li><a href=https://kubernetes.io/docs/reference/access-authn-authz/admission-controllers/#mutatingadmissionwebhook target=_blank rel="noopener noreferrer">MutatingAdmissionWebhook</a> enabled</li>
<li>Istio <a href=https://istio.io/v1.9/ target=_blank rel="noopener noreferrer">v1.9</a> or <a href=https://archive.istio.io/v1.10/ target=_blank rel="noopener noreferrer">v1.10</a></li>
</ul>
<p>Note that Kubernetes version 1.16+ requires Istio version 1.2 or greater.
Note that Istio version 1.9 requires Kubernetes version 1.17-1.20.
Note that Istio version 1.10 is supported on Kubernetes version 1.18-1.21, but has been tested on Kubernetes version 1.22.</p>

<code>mark</code>,<!-- --> <code>multiport</code>, <code>rpfilter</code>, <code>sctp</code>, <code>ipvs</code> (if using<code>kube-proxy</code> in IPVS mode).<li>At least the following actions: <code>REJECT</code>, <code>ACCEPT</code>, <code>DROP</code>,<!-- --> <code>LOG</code>.</ul><li><p>IP sets support.<li><p>Netfilter Conntrack support compiled in (with SCTP support if using SCTP).<li><p>IPVS support if using <code>kube-proxy</code> in IPVS mode.<li><p>IPIP, VXLAN, Wireguard support, if using <!-- -->Calico<!-- --> networking in one of those modes.<li><p>eBPF (including
